# 2026-07-26

- 針對 `copy.bktsai.link` 的 `generate-copy` 504/卡死問題做了 root cause 檢查，確認 live `/health` 當下已切到 `qwen/qwen3.5-plus-02-15`，不是前一天記憶中的 `gpt-5.6-terra`。
- 查到兩個主因：1. `bridge-server.js` 用全域單一 queue，前一個慢請求即使被 nginx 提前斷掉，後面請求仍會在 bridge 內排隊，形成 head-of-line blocking；2. Qwen + OpenRouter 在現有 `generate-copy` 流程下會疊加頁面分析、模型推理與 formatter，導致主流程容易逼近或超過 nginx 預設 timeout。
- 已修正 live `bridge-server.js`：將單一 queue 改成有限併發（預設 `BRIDGE_MAX_CONCURRENCY=2`）、為 OpenRouter 請求補上 `reasoning` 設定（預設 `max_tokens=128` 且 `exclude=true`）、當 HTML 文字訊號已足夠時跳過額外 vision pass，降低單次請求耗時。
- 已補 formatter resilience：`generate-copy` 的母稿/primary copy、以及 `/format-copy` 的 channel formatter 現在若模型回傳髒 JSON 或格式化失敗，會自動 fallback 到 deterministic formatter，不再因 Qwen 偶發不乾淨 JSON 直接回 `502`。
- 已調整正式站 nginx：在 `/etc/nginx/sites-enabled/beck-v1` 補上 `proxy_connect_timeout 180s`、`proxy_send_timeout 180s`、`proxy_read_timeout 180s`，並 reload nginx。
