## 渠道 tab fallback root cause 修正

- 2026-07-29 追查 `Meta 廣告 / Email` 偶發卡住，以及 `SMS / LINE` 偶爾掉成超 generic 備用文案，確認你在前端看到的：
  - `活力補給 - 甘御守重點`
  - `先看產品資訊與使用情境。`
  - `先把產品資訊整理清楚，再決定是否適合你。`
  不是正常 formatter 產物，而是前端 `buildMockChannelCopy()` 的 fallback。
- root cause 有兩個：
  1. `generate-copy` 產出的 `masterDraft` 沒先做長度正規化，但 `format-copy` 入口會驗 `hook / valueProp / cta / toneNote / benefitPoints / proofPoints` 長度；某些 run 一旦母稿欄位太長，`format-copy` 就直接 `400 validation_failed`，前端因此退回 generic fallback。
  2. 前端 `FORMAT_COPY_TIMEOUT_MS` 是 `45s`，但 bridge 先前對上游 channel formatter 會等到 `OPENAI_TIMEOUT_MS=90s`；若上游變慢，前端會先中止並退回 fallback。
- 修正方式：
  - 新增 `normalizeReusableMasterDraft()`，在 `parseMasterDraftOutput()` 與 `normalizeFormatInput()` 都先把可重用母稿收斂到 formatter 驗證上限內。
  - 新增 `CHANNEL_FORMATTER_TIMEOUT_MS`，目前預設取 `min(OPENAI_TIMEOUT_MS, 25000)`，讓 server 比前端更早 fallback，不再拖到前端自己放棄。
- 本地驗證：
  - `node --check bridge-server.js` pass
  - `npm test` 24/24 pass
- live 驗證：
  - 用故意超長的 `masterDraft` 直接 `POST https://copy.bktsai.link/format-copy`（`channel=sms`）已確認回 `200 OK`，不再因 validation 掉 fallback
