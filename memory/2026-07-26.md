- 成本估法基準：當時 live `/health` 顯示模型是 `gpt-5.6-terra`。粗估 `100 篇主要文案` 約 `US$3~6`；`1000 篇主要文案/天` 約 `US$30~60`；若是 `1 主文案 + 5 渠道版`，`1000 篇/天` 約 `US$55~135`。對外討論時可先用這組數字做商業試算，再依實際 token/log 修正。
- 已做過一次完整安全/防呆盤點，重點是：`productUrl` 驗證過鬆，存在 SSRF 風險；API 很可能可被外站濫用來燒 OpenAI 額度（若 production 沒設 `BRIDGE_API_KEY` 且 `cors()` 全開）；長度限制只做在前端、server 可被繞過放大 token 成本；模型輸出的 `url` 也應限制為 `http/https`；目前缺少「產品資訊 vs 爬到頁面資訊不一致」的 mismatch warning；頁面文字/OCR 直接進 prompt，需把 page content 明確標成 untrusted data 以降低 prompt injection 跑偏。若之後要 hardening，優先順序可抓：`URL 限制 + server-side validation + auth/cors 收緊 + mismatch warning`。
- **Security hardening (2026-07-25):** 已完成並部署到 live。URL 一律自動正規化為 `https://`；封鎖 `localhost`、內網 IP、保留網段、自訂 port；server 端補上長度限制（`productName <= 80`、`benefit <= 60`、`productUrl <= 300`）；`/generate-copy` 與 `/format-copy` 已檢查同站 `Origin/Referer`；模型輸出 URL 收斂為安全 `https://`；加上 `產品名稱 vs 頁面資訊` mismatch 檢查；prompt 內將頁面/OCR/截圖標為 untrusted data。
