# 2026-07-18

- `lihi-copy-generator-v1` 已打通 live 鏈路。正式公開頁面是 `<https://lihi-copy-generator-v1.monster7405.workers.dev>`，公開 bridge 是 `<https://lihi-copy.howlihi.com>`。
- 目前架構是 `frontend -> Cloudflare Worker -> named tunnel bridge -> agent session agent:beck-v1:main`。bridge 入口已固定成 named tunnel，但 bridge 程式本體仍跑在本機，不是獨立雲端常駐主機。
- `https://lihi-copy.howlihi.com/` 回 `404` 屬正常行為；這個 hostname 是 API bridge，不是網站首頁。可用路徑至少有 `/health` 與 `/generate-copy`。
- 先前前端一直顯示 `Mock` 的主因不是 agent 或 worker，而是前端 `app.js` URL 組法 bug：把相對 `./api/` 當成 `new URL()` base，瀏覽器會丟 `Invalid URL`，導致送出時直接掉進 mock fallback，且 Network 裡看不到 `/api/generate-copy`。此 bug 已修好並重新 deploy。
- 修正後，硬重整頁面再送出，前端會真的發 `/api/generate-copy`；公開 Worker API 已驗證可回 `mode: live`。
- `beck-v1` 文案器目前的「經驗/知識」來源主要有三層：模型本身的通用行銷寫作能力、`agent:beck-v1:main` 長存 session 的既有指令與歷史脈絡、以及當次表單輸入（產品名稱、3-5 個優點、產品頁連結、tone）。
- 目前這條文案 flow 還沒有獨立外部知識庫/RAG，沒有自動讀 `MEMORY.md`，沒有主動抓產品頁內容，也沒有自動讀 `lihi-shared/` 品牌資產；如果要更可控，下一步可朝品牌知識庫、產品頁抓取與知識使用追蹤前進。
